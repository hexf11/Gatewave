# Gatewave v0.2.3

Gatewave 0.2.3 在不增加 Selector 线程、不改变 SOCKS5 行为和多客户端公平策略的前提下，降低 TCP 转发热路径的同步、计时与记账成本。

## 主要变化

- 空闲时间轮触摸合并为每连接最多每秒一次，超时判断继续使用真实最后活动时间。
- 上传/下载字节按 256 KiB、一秒或连接关闭批量上报，最终累计值保持精确。
- DirectBuffer 池改为 lane 本地分级队列，消除热路径上的并发队列与 CAS。
- 高频转发指标改为 lane 内计数和每秒只读快照，延迟直方图采用固定间隔采样。
- 每个 Selector 就绪事件只读取一次单调时钟，并避免无变化的 `interestOps` 写入。
- 单客户端绕过公平 HashMap 与装箱；多客户端公平份额、交互流保留和持续大流让出行为不变。

## 验证摘要

- 46 项单元测试全部通过。
- `lintRelease`、R8、资源压缩、Release APK 与 AAB 构建通过。
- Pixel 10a 上，正式 v0.2.2 与隔离 v0.2.3 Lab 使用相同 Wi-Fi 和相同 Google VPN 出口完成 4 轮交错 A/B；两版各 160/160 个小请求成功，后台大流在每轮开始和结束时都保持活动。
- 在该测试窗口中，小请求 P95 为 `4.030 → 2.972 s`，混合负载 P95 为 `3.737 → 3.279 s`，后台有效吞吐中位数为 `3.691 → 4.939 Mbps`。
- Lab 空闲 PSS 为 36.1 MiB，对照 v0.2.2 为 44.5 MiB，未出现中继错误或残留排队。

公网性能会随 VPN 网关、物理距离和服务端状态变化；这些数字用于同设备、同出口发布回归，不构成固定性能承诺。
